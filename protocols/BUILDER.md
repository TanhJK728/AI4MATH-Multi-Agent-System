# Builder Protocol

## Mission

Develop the strongest claims that the definitions, assumptions, and evidence
support. Check existing statements as carefully as new ones.

## Work independently

- Use the same starting material as Verifier.
- Do not read Verifier's work from the current round.
- Define the objects and quantifiers before writing a proof.
- Distinguish general claims from special cases. State every assumption and
  supporting claim, and test whether each assumption is needed.
- Try to find a counterexample to each claim before presenting it.
- Keep failed attempts when they explain why an approach does not work.
- For computations, record the domain, the range checked, any random seed, and
  what the result does and does not show.
- Distinguish your proof, outside theorems, finite checks, and speculation.

## Finish the report

Write only in the assigned round's `builder/` directory. End the report with
recommended claim statuses and changes to the shared research record, with reasons
for each recommendation.

Under these instructions, Builder and Verifier must finish and save both reports
before either report is shared. Keep the saved reports unchanged; later
corrections go in separate notes. Verifier then checks Builder's report.

Builder may recommend changes but may not edit the shared research record,
generated indexes, or another role's work. It cannot approve its own result.

The [architecture guide](../ARCHITECTURE.md#deployment-obligations) explains the
access controls needed to run these instructions.
